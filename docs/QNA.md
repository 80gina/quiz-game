## 항목 1. 기능 동작 검증 (7문항)

### <a id="q1-1"></a>1-1. 메뉴가 표시되고 퀴즈 풀기/추가/목록/점수 확인이 모두 동작하는가?
- 답: 네. `python main.py`(Windows는 `py main.py`)로 실행하면 메뉴가 나옵니다. 1 풀기, 2 추가, 3 목록, 4 점수 확인, 5 종료가 모두 동작하고, 추가로 6번 AI 패턴 퀴즈가 있습니다. 증빙은 README 7장 스크린샷입니다.

### <a id="q1-2"></a>1-2. 정답/오답 판정이 정확하고 입력 오류(공백/문자/범위 밖/빈 입력)를 처리하는가?
- 답: `read_int()` 한 곳에서 모두 처리합니다.
  - 앞뒤 공백 → `strip()`으로 제거
  - 빈 입력 → "빈 입력입니다. 숫자를 입력하세요."
  - 문자(`abc`) → "숫자만 입력하세요."
  - 범위 밖(메뉴 9, 정답 0) → "1~N 사이의 숫자를 입력하세요."
  - 어느 경우든 안내 후 **같은 질문으로 돌아가 다시 입력**받습니다.
- 판정은 `Quiz.is_correct(choice)`가 입력 번호와 정답 번호를 비교합니다.

### <a id="q1-3"></a>1-3. 종료 후 재실행해도 추가한 퀴즈와 최고 점수가 유지되는가?
- 답: 네. 퀴즈를 풀거나 추가하거나 종료할 때 `state.json`에 저장하고, 실행할 때 `load()`로 불러옵니다. 퀴즈를 추가하고 껐다 켜서 목록과 최고 점수가 그대로인 것을 스크린샷으로 확인했습니다.

### <a id="q1-4"></a>1-4. 기본 퀴즈가 5개 이상인가?
- 답: 네. 숲해설·환경교육 주제로 `default_quizzes()`에 5개를 작성했습니다. 각 퀴즈는 문제, 선택지 4개, 정답 번호를 가집니다. `state.json`이 없으면(첫 실행) 이 기본 퀴즈를 씁니다.

### <a id="q1-5"></a>1-5. GitHub에 코드가 올라가 있고 10개 이상의 의미 있는 커밋이 있는가?
- 답: 네. 커밋은 **32개**이고, `Feat:`, `Docs:`, `Merge:`처럼 작업 내용을 드러내는 접두어와 요약으로 기능 단위(메뉴, Quiz, 기본 데이터, 풀기, 추가, 목록, 점수, 저장, README…)로 나눴습니다.

### <a id="q1-6"></a>1-6. 브랜치 생성·병합이 `git log --oneline --graph`에서 확인되는가?
- 답: 네. `git checkout -b feature/play-quiz`로 브랜치를 만들어 퀴즈 풀기를 개발하고 `main`에 병합했습니다. 이후 `feature/npu-quiz`도 병합해 병합이 **2회**입니다. `--no-ff`로 병합해서 갈라졌다 합쳐지는 모양이 그래프에 남습니다(`S14_merge`, `N10_merge2`).

### <a id="q1-7"></a>1-7. clone과 pull 실습 흔적이 있는가?
- 답: 네. README 9장에 있습니다. `git clone`으로 별도 폴더(`quiz-game-clone`)에 복제하고, 복제본에서 README에 한 줄을 추가해 commit → push했습니다. 원래 폴더에서 `git pull`로 가져와 반영을 확인했습니다.

## 항목 2. 코드 구조 및 설계 (5문항)

### <a id="q2-1"></a>2-1. Quiz와 QuizGame의 책임을 어떻게 나눴나요?
- 답: `Quiz`는 **한 문제**를 맡습니다. 속성은 `question`, `choices`, `answer`이고 메서드는 `show()`(출력), `is_correct()`(채점), `to_dict()`/`from_dict()`(JSON 변환)입니다. `QuizGame`은 **게임 전체**를 맡습니다. 퀴즈 목록과 `best_score`를 갖고 메뉴, 풀기, 추가, 목록, 점수, 저장·불러오기를 처리합니다. 한 문제의 일과 전체 진행의 일을 나눠야 문제 구조가 바뀌어도 게임 진행 코드를 덜 고칩니다.
- 보너스 연결: `PatternQuiz`가 `Quiz`를 상속해 `show()`만 바꿔 씁니다.

### <a id="q2-2"></a>2-2. 입력 처리, 게임 진행, 저장/불러오기를 어떤 기준으로 분리했나요?
- 답: **"바뀌는 이유"가 다른 것끼리** 나눴습니다.
  - 입력: `read_line()`, `read_int()` (검증과 Ctrl+C 처리)
  - 진행: `play()`, `add_quiz()`, `list_quizzes()`, `show_score()`
  - 저장: `load()`, `save()`
- 입력 규칙이 바뀌면 입력 함수만, 저장 형식이 바뀌면 저장 함수만 고치면 됩니다.

### <a id="q2-3"></a>2-3. `state.json` 읽기/쓰기는 어디서 어떤 순서로 일어나나요?
- 답: ① 프로그램 시작 시 `QuizGame.__init__`이 `load()`를 호출해 읽습니다(없으면 기본 퀴즈, 손상이면 복구). ② 실행 중 퀴즈를 풀어 최고 점수가 갱신될 때, 퀴즈를 추가할 때, 종료할 때 `save()`로 씁니다. 저장은 UTF-8, `ensure_ascii=False`이고, **임시 파일(`state.json.tmp`)에 먼저 쓴 뒤 `os.replace()`로 교체**해서 쓰는 도중 꺼져도 기존 파일이 안전합니다.

### <a id="q2-4"></a>2-4. Ctrl+C 또는 EOF에서 안전 종료를 위해 어떤 처리를 했나요?
- 답: 모든 입력이 `read_line()`을 거치도록 모아서 `try/except (KeyboardInterrupt, EOFError)`로 감싸고, 예외가 나면 `None`을 반환합니다. 그리고 `install_signal_handlers()`가 **SIGTERM(종료 요청)과 SIGHUP(터미널 끊김)을 Ctrl+C와 같이 취급**하도록 등록해 두었습니다(윈도우에는 SIGHUP이 없어 있는 신호만 등록). 강제 종료(`kill -9`)는 어떤 프로그램도 막을 수 없다고 README 13-4에 밝혀 두었습니다. 호출한 쪽이 `None`을 보면 "입력이 중단되었습니다. 종료합니다."를 출력하고 **저장 후 종료**합니다. 그래서 Traceback 없이 끝납니다.

### <a id="q2-5"></a>2-5. 커밋을 어떤 단위로 나누고 메시지 규칙은?
- 답: **기능 하나가 끝날 때마다 커밋**했습니다(메뉴, Quiz, 기본 데이터, 풀기, 추가, 목록, 점수, 저장, README). 메시지는 `Feat:`(기능), `Fix:`(수정), `Docs:`(문서), `Merge:`(병합) 접두어 + 작업 내용 요약입니다. 커밋 메시지가 기능과 다르게 적힌 적이 있어 push 전에 `git commit --amend -m`으로 고쳤습니다(README 10장).

## 항목 3. 핵심 기술 원리 적용 (5문항)

### <a id="q3-1"></a>3-1. 클래스를 쓴 이유, 함수만 쓸 때와의 차이는?
- 답: 데이터와 그 데이터를 다루는 동작을 한 덩어리로 묶기 위해서입니다. 함수만 쓰면 문제·선택지·정답을 따로 흘려 보내야 하고 어떤 데이터가 어떤 함수 것인지 헷갈립니다. 클래스는 `Quiz` 객체 하나가 자기 정보와 채점 방법을 같이 가지므로 코드를 읽기 쉽고, `PatternQuiz`처럼 **상속으로 확장**하기도 쉽습니다. `__init__`은 객체를 만들 때 속성을 채우는 메서드이고, `self`는 "지금 이 객체 자신"입니다.

### <a id="q3-2"></a>3-2. JSON으로 저장하는 이유와 특징은?
- 답: 파이썬의 `list`·`dict`와 모양이 거의 같아 변환이 쉽고, 텍스트라 사람이 열어 읽고 고칠 수 있으며, 다른 언어·프로그램과도 주고받을 수 있습니다. 프로그램을 꺼도 파일에 남아 **데이터 영속성**을 얻습니다. 단, 숫자·문자열·리스트·객체·`null`·불리언만 표현하므로 `Quiz` 객체는 `to_dict()`로 바꿔 저장하고 `from_dict()`로 되돌립니다.

### <a id="q3-3"></a>3-3. 파일 입출력에서 `try/except`가 필요한 이유는?
- 답: 코드가 맞아도 파일은 밖의 세계라 실패할 수 있기 때문입니다. 저장은 일시적 실패에 대비해 **최대 3번(0.2초 간격) 재시도**하고, 그래도 안 되면 원인(권한·디스크)을 안내하고 계속 실행합니다. 발생 가능한 경우는 ① 파일 없음(첫 실행, `FileNotFoundError`), ② 내용이 깨짐/직접 편집 실수(`JSONDecodeError`), ③ 키·형식이 다름(`KeyError`, `TypeError`, `ValueError`), ④ 권한·디스크 문제(`OSError`)입니다. 처리하지 않으면 프로그램이 Traceback으로 죽습니다.

### <a id="q3-4"></a>3-4. 브랜치를 분리한 이유와 병합의 의미는?
- 답: 새 기능을 만들다가 `main`을 망가뜨리지 않으려고 따로 작업 공간을 만든 것입니다. 병합 전 `main`에는 퀴즈 풀기가 없었고("준비 중"), 병합 후에 기능이 합쳐졌습니다(`S13`, `S14`). 병합(merge)은 브랜치의 작업 내용을 `main`에 합치는 것이고, 이 기록이 그래프에 남습니다.

### <a id="q3-5"></a>3-5. `state.json` 구조를 지금 형태로 설계한 이유는?
- 답: 요구된 최소 스키마 `quizzes`(리스트)와 `best_score`(정수 또는 `null`)를 따랐습니다. 퀴즈는 `question`, `choices`(4개 리스트), `answer`(1~4 정수)를 가진 객체의 리스트입니다. 이유는 ① `Quiz` 클래스 속성과 1:1로 대응해 변환이 단순하고, ② 퀴즈 추가 = 리스트에 객체 하나 추가라 확장이 쉽고, ③ 점수처럼 전체에 하나뿐인 값은 최상위에 둔 것입니다. 정답을 0이 아닌 1~4로 둔 것은 사용자가 입력하는 번호와 같게 해 변환 실수를 막기 위해서입니다.

## 항목 4. 심층 인터뷰 (3문항)

### <a id="q4-1"></a>4-1. 퀴즈가 1000개 이상이 되면 JSON 방식의 한계는?
- 답: **직접 측정한 결과(README 13-1)** 로 말합니다. 저장·불러오기·메모리·검색이 모두 **O(n)** 입니다.

| 퀴즈 수 | 저장 평균 (최소~최대) | 불러오기 평균 (최소~최대) | 파일 | 메모리 |
|---|---|---|---|---|
| 1,000 (5회) | 15.8ms (12.9~17.5) | 55.7ms (44.0~61.9) | 185KB | 1.0MB |
| 10,000 (5회) | 120.6ms (112~128) | 198.4ms (182~231) | 1.8MB | 9.5MB |
| 100,000 (3회) | 2038ms (1635~2272) | 3500ms (3371~3667) | 18MB | 94MB |

- 단일 측정이 아니라 **반복 측정의 평균과 범위**입니다. 흔들림은 ±15% 안팎이라 결론은 같습니다.
- **1000개에서는 문제가 없습니다.** 한계는 **수만 개 이상**에서 보입니다. 퀴즈를 추가할 때마다 **전체 파일을 다시 쓰기** 때문입니다(10만 개에서 약 2초).
- 그 밖의 한계: ① 시작할 때 전부 메모리에 올림 ② 조건 검색은 처음부터 훑음 ③ 동시에 여러 프로그램이 쓰면 충돌 ④ 수정·삭제 이력과 관계(카테고리, 풀이 기록)를 표현하기 어려움.
- 대안: SQLite(`sqlite3`, 인덱스·일부만 읽고 쓰기·트랜잭션)나 카테고리별 파일 분리. 지금 규모(수십 개)에는 JSON이 단순해서 적합합니다.

### <a id="q4-2"></a>4-2. `state.json`이 손상되어 파싱에 실패하면 데이터를 잃지 않게 하려면?
- **구현한 것 (평가 피드백 반영, 커밋 `a5e2806`):**
  1. **손상 감지:** `JSONDecodeError`, `KeyError`, `TypeError`, `ValueError`, `OSError`를 잡고 안내 후 프로그램이 죽지 않게 합니다.
  2. **백업 보관:** 복구하기 **전에** 손상 파일을 `state.json.bak`로 이름을 바꿔 보관합니다. 사용자가 추가한 퀴즈를 되살릴 수 있고, 수동 복구는 `.bak`를 고쳐 `state.json`으로 바꾸면 됩니다.
  3. **원자적 저장:** `state.json.tmp`에 먼저 쓰고 성공하면 `os.replace()`로 교체해 **쓰는 도중 꺼져도 기존 파일이 안전**합니다.
  4. **저장 실패 안내:** 권한·디스크 문제는 원인과 확인 방법을 안내하고 계속 실행합니다.
  5. **재시도:** 일시적 저장 실패는 최대 3번 다시 시도합니다.
- **남은 한계(솔직하게):** `.bak`는 **한 세대만** 보관하고(손상이 연속되면 덮어씀), 일부 항목만 깨졌을 때 정상 항목을 살리는 부분 복구는 하지 않습니다. 개선하려면 날짜별 백업과 항목 단위 검증을 추가합니다.
- 보여 줄 증빙: README 13-3, 그리고 손상 파일로 실행하면 "(손상된 파일은 state.json.bak로 보관했습니다.)"가 출력됩니다.

### <a id="q4-3"></a>4-3. 채점 방식이나 퀴즈 구조(선택지 개수)가 바뀌면 어디를 먼저 수정하나요?
- 답:
  - **채점 방식(점수 계산)**: `QuizGame.play()`의 점수 계산 부분과 `show_score()`를 고칩니다. 한 문제의 정답 판정이 바뀌면 `Quiz.is_correct()`입니다.
  - **선택지 개수**: `NUM_CHOICES` 상수를 먼저 바꿉니다. 이 값이 `from_dict()` 검증, `play()`의 정답 범위, `add_quiz()`의 입력 횟수와 정답 범위에 쓰입니다(평가 피드백 후 한 곳으로 모음). 그다음 기본 퀴즈 데이터 `default_quizzes()`와 **기존 `state.json` 호환**(옛 파일은 손상으로 판단되어 `.bak`로 보관됨)을 확인합니다.
  - 저장 방식이 바뀌면 `load()`, `save()`만, 입력 규칙이 바뀌면 `read_line()`, `read_int()`만 고치면 됩니다. 전체 표는 README 13-2에 있습니다.
  - **고친 뒤 확인:** `python test_quizgame.py`로 **자동 테스트 19개**를 돌리고, README 14-10의 회귀 체크리스트 5항목(테스트 → 기본 퀴즈 5개 → 풀기·추가·재실행 → 손상 파일 → 이상 입력)을 따릅니다.
- 책임을 나눠 둔 덕분에 문제 구조는 `Quiz`, 진행·점수는 `QuizGame`으로 수정 범위가 좁혀집니다.

### 추가 예상 질문 (2차 평가 피드백 반영 후)

### <a id="q4-4"></a>4-4. 자동 테스트는 무엇을 검증하나요?
- 답: 표준 라이브러리 `unittest`로 **19개**를 만들었습니다. `Quiz`의 채점·변환·형식 검증(5), `QuizGame`의 입력 검증(3), 메뉴 시나리오·점수·재시작 후 유지·EOF 종료(5), 저장/불러오기·손상 `.bak`·임시 파일 교체·재시도(5), SIGTERM 핸들러(1)입니다. **임시 폴더의 파일로 실행**하므로 실제 `state.json`은 바뀌지 않습니다. 책임을 나눠 둔 덕분에 `Quiz`와 `QuizGame`을 따로 시험할 수 있었습니다.

### <a id="q4-5"></a>4-5. 두 프로그램이 동시에 실행되면?
- 답: 나중에 저장한 쪽이 이깁니다(마지막 저장 우선). 임시 파일 후 교체라 **파일이 반쯤 쓰이는 일은 없지만** 두 변경이 합쳐지지는 않습니다. 그래서 한 번에 하나만 실행하고, 여러 명이면 각자 복제본에서 실행하며, 퀴즈는 `퀴즈 추가` 메뉴로 넣도록 권장 절차를 README 14-3에 적었습니다.

### <a id="q4-6"></a>4-6. 추상 클래스(ABC)를 안 쓴 이유는?
- 답: 강제로 같은 메서드를 갖게 하는 장점은 있지만, 클래스가 늘어 복잡해지고 퀴즈 종류가 지금은 2개(`Quiz`, `PatternQuiz`)뿐이라 상속으로 충분했습니다. 종류가 늘면(OX, 주관식) 도입합니다(README 14-8).

### <a id="q4-7"></a>4-7. `category` 필드는 왜 추가했나요?
- 답: 평가에서 향후 확장용 메타를 제안받았습니다. 선택 필드라 **옛 `state.json`도 그대로 읽히고**(기본값 `일반`), 테스트로 확인했습니다.

## <a id="q5"></a>항목 5. 보너스 (크레딧)
- 현재 구현 상태: 필수 요구는 모두 충족했고, 보너스(랜덤 출제, 문제 수 선택, 힌트, 삭제, 점수 히스토리)는 **본 퀴즈에는 구현하지 않았습니다.**
- 대신 **3번 미션 연결 기능(메뉴 6 AI 패턴 퀴즈)** 을 추가했습니다: `PatternQuiz` 상속, `npu_core.py`(MAC·정규화·허용오차), `data.json` 형식 공유, `random.sample`로 패턴 문제를 무작위 출제, `feature/npu-quiz` 브랜치 개발 후 병합, [mini-npu](https://github.com/80gina/mini-npu)와 링크 연결.
- 점수를 더 받고 싶다면 가장 쉬운 보너스는 **랜덤 출제**(`random.shuffle`)와 **퀴즈 삭제**입니다. (원하면 다음에 추가할 수 있습니다.)
